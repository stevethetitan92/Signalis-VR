# SIGNALIS VR 0.7.166 — launcher candidate

This candidate adds independent SteamVR and Virtual Desktop launchers, automatic Steam-library discovery, a pasted-path prompt and automatic diagnostics after a pasted path fails.

- **SteamVR:** original Valve OpenVR provider. Virtual Desktop is not required.
- **Virtual Desktop:** VDXR through the bundled OpenComposite provider. SteamVR is not required.
- Both require the Steam game/client and the chosen headset connection. Neither launcher changes system-wide runtime registry settings or installs prerequisites.

Diagnostics check paths/manifests, launcher syntax/checksums, required files/hashes, native bridge/provider DLL loading and exports, and selected connection software. They save a report, can recover a uniquely verified game location, and otherwise allow retry/cancellation. `Diagnose Launcher.cmd` runs independently of the main launch script. No game or VR session is initialized by diagnostics, and no automatic file repair/install occurs.

## Verification

114 regression checks, 18 launcher checks and 16 diagnostic checks passed. All three actual command wrappers were tested; two deterministic mod builds matched. The unchanged native bridge passed its simulated 2,000-frame D3D11 WARP/fake-compositor harness. Provider policy and 10,000 simulated focus loss/recovery cycles passed. Embedded resources and existing native/companion dependencies were verified; archive entries were checked against SHA256 manifests.

**No new game/headset session was launched.** Both connection paths still require real headset startup, both-eye graphics, input/reload/IK, computer/disk interactions, maps, markers, enemies/burn effects, reflections, runtime interruption and performance validation. Stable 60fps is not established.

The mod is based on preserved 0.7.163 logic. Five compiled files change for provider selection, focus, diagnostic provenance and version metadata. Unfinished 0.7.164/0.7.165 performance work and paused Blender work are excluded. Gameplay, original enemy counts/AI, existing textures/assets and native rendering policies were not changed for this launcher update.

OpenComposite's SteamVR scene-focus query is unsupported; the VD path uses its OpenXR focused-session availability instead. Estimated GPU timing fields and its fixed 90Hz device property are not treated as measurements. Optional `-RefreshRate` matches the user's actual VD setting; otherwise VD uses a conservative, explicitly logged 72Hz pacing fallback. SteamVR reads its own validated refresh rate.
